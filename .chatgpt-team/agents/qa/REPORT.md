### P1 — Blocking frozen contract inconsistency — VERIFIED
**Code:** `backend/app/modules/identity/router.py` `check_invitation_quota()` returns `IdentityError(409, "INVITE_RATE_LIMITED")` when either 20 per (company, issuer) or 50 per company in rolling UTC 24h is reached. `IdentityRoute` serializes this as `{"error":{"code":"INVITE_RATE_LIMITED",...}}`. The code is reachable after 20 successful distinct-email invitations; tests `test_invite_distinct_emails_rate_limited_and_persisted_across_engines`, `test_company_cap_blocks_multi_issuer_bypass_and_other_tenant_is_independent`, `test_invitation_actor_quotas_are_isolated_within_company_and_window` explicitly assert this emitted value.
**Frozen API:** `POST /companies/{companyId}/members` has HTTP `409` `#/components/responses/Conflict`, whose `ErrorEnvelope.error.code` references the *closed* `#/components/schemas/ErrorCode.enum`. **`INVITE_RATE_LIMITED` is absent** from this enum. It is also **absent** from `docs/contracts/ERRORS.md`; the taxonomy explicitly prohibits unspecified catch-all codes without contract update. Thus HTTP status 409 is declared, but its actual body violates the frozen schema. Coordinator's characterization of this as an "existing contract-compatible" error code is not supported by the actual normative schema.
**Impact:** OpenAPI-generated clients/validators and Persian client error mapping have no declared `INVITE_RATE_LIMITED` code. Rate limit is a common deterministic condition, not an unreachable edge. **Acceptance criterion "exactly matching frozen OpenAPI 1.0.0-rc.3" fails.**
**Required gate:** Developer/Coordinator/Manager must select and approve a contract-safe error semantics remedy; any addition to frozen `ErrorCode` requires a formal Manager-authorized Coordinator-owned contract revision and consumer coordination, not a unilateral H-05 Developer/QA change. Alternatively use an *existing semantically valid* documented code only if authorized and justified; do not silently repurpose `INVITE_INVALID` as rate-limited. Add an automated response-schema assertion at quota boundary, rerun tests on new exact SHA, Coordinator re-review, then independent QA and Manager gate. **No files changed by QA except QA report.**
